# 重复度与 Pods 依赖可视化展示方案

本文档说明**代码/资源重复**与 **Pods 依赖**在 App 内如何做可视化展示的可行方案，供后续迭代选型与实现参考。

**已实现（可视化 TAB）**：  
- **重复度**：在可视化 TAB 增加「重复度」子 Tab（`DuplicateTabView`），分「代码重复」「资源重复」两区，每组可展开查看路径列表。  
- **Pods 依赖**：在可视化 TAB 增加「Pods依赖」子 Tab（`PodsDependencyTabView`），使用 `OutlineGroup` 树形展示 Pod 名称、版本、体积（estimatedSize 有值时显示）。

---

## 一、现状

- **分析结果**：`AnalysisProject` 已包含 `duplicateCodeGroups`、`duplicateResourceGroups`、`podsDependencyResult`，在分析摘要（Analysis TAB）中以卡片形式展示「X 组」「X 个」及一句说明。
- **可视化 TAB**：当前主要为 **Treemap** 与 **按文件夹展开**，基于 `analysisResults`（文件级体积与无用标记），**未**对「重复组」「Pods 列表」做专门图表或列表视图。

---

## 二、代码/资源重复度可视化

### 2.1 目标

- 让用户一眼看到「哪些重复组体积大、份数多」，便于优先处理高价值去重。
- 支持下钻：从组 → 组内各份路径列表，可复制路径或在 Finder 中定位。

### 2.2 方案 A：分析 TAB 内「重复」子区（列表 + 简单图表）

- **位置**：在现有分析结果区（`AnalysisSummaryView`）下方或折叠区内，当 `duplicateCodeGroups` / `duplicateResourceGroups` 非空时展示。
- **代码重复**：
  - 表格：列 = 组 ID/指纹缩写、份数、涉及文件数、可选「预估可省行数/体积」；行可展开显示该组下所有 `DuplicateCodeEntry.relativePath`。
  - 或条形图：X 轴 = 组（按份数或可省体积排序），Y 轴 = 份数或总行数，便于对比。
- **资源重复**：
  - 表格：列 = 组、份数、总大小（totalSize）、涉及路径数；行可展开列出各 `DuplicateResourceEntry.relativePath` + size。
  - 或条形图：Y 轴 = totalSize（可省空间），X 轴 = 组，突出「省空间大」的组。
- **交互**：行点击展开/折叠；支持「复制路径」「在 Finder 中显示」等上下文菜单。
- **优点**：实现简单，与现有摘要同屏，无需新 Tab。  
- **缺点**：组数很多时需分页或限制展示条数。

### 2.3 方案 B：可视化 TAB 内新增「重复」子 Tab

- **位置**：与 Treemap、按文件夹展开并列，增加第三个 Tab「重复分析」。
- **内容**：
  - 上半区：代码重复组列表（同 2.2），可带简单条形图。
  - 下半区：资源重复组列表（同 2.2），可带简单条形图。
  - 或左右分栏：左代码、右资源。
- **优点**：与「体积 Treemap」分离，专注重复维度；可复用可视化 TAB 的 project 上下文。  
- **缺点**：多一个 Tab，需维护一套列表/图表 UI。

### 2.4 方案 C：Treemap 上叠加「重复」高亮（进阶）

- 在现有 Treemap 或按文件夹展开的树中，对「属于某重复组的路径」做高亮（如描边或背景色），点击可弹出该组详情。
- **优点**：与空间分布结合，看到重复文件在工程中的位置。  
- **缺点**：需将「组 → 路径集合」与树节点做匹配；实现与性能成本较高，可作为后续增强。

**建议**：先做 **方案 A**（分析 TAB 内列表 + 可选条形图），满足「看到组、下钻到路径」；若后续需要更强「重复视角」再加方案 B。

## 三、Pods 依赖可视化

### 3.1 目标

- 展示当前分析项目依赖的 Pod 列表（名称、版本），可选展示预估体积。
- 若后续有树形子依赖（children），可展示层级关系。

### 3.2 方案 A：分析 TAB 内「Pods 依赖」子区（表格式）

- **位置**：在分析结果区，当 `podsDependencyResult?.pods` 非空时，在 Pods 卡片下方展开表格。
- **表格列**：Pod 名称、版本、预估体积（若 `estimatedSize > 0`）、子依赖数（若已有 children）。
- **交互**：行可展开显示 children；支持按名称/体积排序。
- **优点**：与摘要同屏，实现简单。  
- **缺点**：树形依赖若层级深，表格展示会略占空间。

### 3.3 方案 B：可视化 TAB 内「Pods」子 Tab（列表/树 + 可选饼图）

- **位置**：与 Treemap、按文件夹展开、重复分析（若做）并列，增加「Pods 依赖」Tab。
- **内容**：
  - **列表/树**：顶层 Pod 列表，可展开子依赖（children）；列显示名称、版本、estimatedSize。
  - **饼图**：当 `estimatedSize` 有数据时，按 Pod 占比画饼图，便于看出「谁占体积大」。
- **优点**：专门视角，适合多 Pod 工程；饼图直观。  
- **缺点**：当前 `PodsDependencyScanService` 未填 `estimatedSize`，需先接 LinkMap/包内路径才能有占比数据。

### 3.4 方案 C：与 Treemap 结合（Pods 路径在树中高亮）

- 在按文件夹展开或 Treemap 中，对路径属于 `Pods/XXX` 的节点做区分（如不同颜色或图标），与「主工程」「资源」等区分开。
- **优点**：空间分布 + 依赖归属一体。  
- **缺点**：需在现有树节点上增加「所属 Pod」属性或匹配逻辑，可作为后续增强。

**建议**：先做 **方案 A**（分析 TAB 内 Pods 表格，支持按名称/版本排序，可选展开 children）；待 `estimatedSize` 有数据后再在方案 A 或 B 中加饼图。

---

## 四、实现优先级与依赖

| 能力 | 建议方案 | 依赖 |
|------|----------|------|
| 代码重复展示 | 分析 TAB 内「代码重复」列表 + 行展开显示路径 | 无，数据已有 |
| 资源重复展示 | 分析 TAB 内「资源重复」列表 + 行展开显示路径 | 无，数据已有 |
| Pods 依赖展示 | 分析 TAB 内「Pods 依赖」表格（名称、版本、可选 children） | 无，数据已有 |
| 重复组条形图 | 方案 A 中可选条形图（份数或 totalSize） | 同上 |
| Pods 饼图 | 方案 A/B 中饼图 | 需 estimatedSize（LinkMap/包内路径匹配） |
| 可视化 TAB 独立「重复」「Pods」Tab | 方案 B | 与上可共用列表/表格组件 |

---

## 五、小结

- **分析历史选中加载**：侧边栏已改为 `List(selection:)` 绑定 `selectedProjectId`，选中即同步 `currentProject`，实现「选中加载」。
- **重复度可视化**：优先在分析 TAB 内用列表 + 行展开展示代码/资源重复组及路径；可选简单条形图；进阶再考虑可视化 TAB 独立 Tab 或 Treemap 高亮。
- **Pods 可视化**：优先在分析 TAB 内用表格展示 Pod 列表（名称、版本、children）；待 estimatedSize 有数据后可加饼图或独立 Pods Tab。

以上方案与现有数据模型和 UI 结构兼容，可按优先级分阶段落地。
