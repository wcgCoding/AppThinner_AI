## ios-package-optimization SKILL 使用说明

一个基于 AppThinner 导出的 AI 报告 JSON，生成标准化 **iOS 安装包优化分析报告 + 瘦身执行任务清单** 的 SKILL。

### 1. 能力概览

- **输入**：  
  - 必填：AppThinner 导出的 JSON 文件路径（例如 `ai-optimization-report-MyApp.json`）  
  - 可选：  
    - `mode`：`"report"` / `"report+execute"`（默认）  
    - `businessToSunset`：拟下架业务配置（如 `["直播","歌房","录唱","短视频"]` 或带关键字映射的对象）

- **输出**：  
  - 一份完整的 HTML 报告（使用 `assets/report-template.html` 模板渲染），包含：  
    - 总体积 & 可节约空间概览  
    - 体积分布与热点模块  
    - 无用代码与无用资源清理建议  
    - 拟下架业务与可清理范围（如配置了 `businessToSunset`）  
    - Pods 依赖优化建议  
    - 优先级规划 & 风险提示  
  - （在 `mode: "report+execute"` 下）一份 **瘦身执行任务清单**（Markdown/结构化数据），仅描述「要做什么」和「预估收益」，**不直接改代码或删文件**。

### 2. 模式说明

- `mode: "report"`  
  - 只生成 HTML 报告，不输出执行任务清单。

- `mode: "report+execute"`（默认推荐）  
  - 在生成报告的基础上，额外按三类生成任务列表：  
    1. **明确的无用资源 / 无用代码删除**：来源于 `unusedResources` / `unusedCode`，列出候选文件、相对路径、体积与建议动作。  
    2. **尝试下架某个 Pods 库**：基于 `podsDependencies.mainLibSummary` 与依赖关系，给出体积大、无用占比高或只被边缘业务依赖的 Pods 建议。  
    3. **尝试下架某一个业务场景（TODO）**：结合「拟下架业务」分析结果，给出高层级下架建议（入口关闭、主要目录、端上与 Pods 预估收益），当前版本不自动展开到具体改动。

> 无论哪种模式，SKILL 本身**不会直接修改 Xcode 工程、Podfile 或物理文件**，所有改动都应在阅读任务清单后由开发者或后续自动化流程显式执行。

### 3. 拟下架业务（businessToSunset）

如在调用时提供拟下架业务配置（例如下架「直播」「歌房」「录唱」「短视频」），SKILL 会在报告中插入「四、拟下架业务与可清理范围」章节，并：

- 基于 `relativePath` 的路径关键字匹配（不区分大小写），统计每类业务：
  - 端上源码可节约体积（排除 Pods）  
  - 无用代码 / 无用资源条数与体积（基于 `unusedCode` / `unusedResources` Top 500）  
  - 疑似关联 Pods 的体积与库名（展示在可展开明细中）
- 输出汇总表格 + 每类业务的简短落地建议。

### 4. 推荐使用方式

1. 在 AppThinner 中对分析项目执行「Treemap 可视化 → 导出 AI 报告数据」，得到 JSON。  
2. 调用本 SKILL，传入：  
   - JSON 路径  
   - 可选的 `businessToSunset` 配置  
   - （若不想要任务清单）显式指定 `mode: "report"`  
3. 查看生成的 HTML 报告，确认整体优化方向与拟下架业务收益。  
4. 在 `mode: "report+execute"` 下，阅读「瘦身执行任务清单」，按三类任务逐步在独立分支中落地改动，并结合编译/回归验证结果迭代。

### 5. 外部数据导入与样例模版

SKILL 也支持在分析时**参考外部数据**（例如线下整理好的「待删除类/资源名单」、线上埋点统计的「极少访问页面」列表等），用于在报告和执行任务清单中打标签或做交叉验证。

- 推荐的外部数据格式与字段说明，见同目录下的 `external-data-template.md`。  
- 典型用途：
  - 在「无用代码与无用资源清理建议」章节中高亮「同时出现在外部名单中的文件」；
  - 在执行任务清单中标记「来自外部数据的强烈建议项」，帮助优先排期。

> 具体如何把外部数据注入到 SKILL 的上下文，由上层调用方决定（例如在对话中粘贴、提供额外文件路径等）；本 README 仅给出推荐的数据结构模版。
